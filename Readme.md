# Практическое задание 2. Склад с резервированием товаров (REST API + PostgreSQL)

## 1. Бизнес-требования и реализованный функционал
Сервис учёта товаров, складских остатков и заказов для приёма заказов из разных каналов с гарантией отсутствия перепродажи (оверселлинга):
- **Управление товарами:** создание товара с уникальным `SKU`, положительной ценой и неотрицательным остатком; просмотр карточки товара; получение списка с поиском по `SKU`/названию и пагинацией (`limit`, `offset`).
- **Управление остатками:** изменение остатка через относительное приращение (`delta`) или установку абсолютного значения (`stock`) с запретом ухода в минус.
- **Атомарное резервирование заказа:** заказ резервирует все позиции целиком в рамках одной транзакции БД. При нехватке хотя бы одной позиции происходит откат (`rollback`), частичное списание не выполняется.
- **Правило дублей SKU:** повторяющиеся `SKU` в одном заказе отклоняются с кодом `422 Unprocessable Entity`.
- **Фиксация цены:** цена каждой позиции (`unit_price`) копируется из карточки товара в момент создания заказа и не меняется при последующем изменении цены товара.
- **Транзакционная отмена:** отменить можно только заказ в статусе `Reserved` (остатки возвращаются на склад). Повторная отмена отклоняется (`409 Conflict`) и не меняет остаток.

## 2. Архитектура проекта
Приложение разделено на три независимых слоя и SQL-миграцию:
- `migrations/init.sql` — повторяемый SQL-скрипт создания таблиц (`products`, `orders`, `order_items`) и ограничений целостности (`UNIQUE`, `CHECK (stock >= 0)`, `CHECK (price > 0)`).
- `src/repository.py` — слой работы с PostgreSQL: подключение через `DATABASE_URL`, накатка миграций, параметризованные SQL-запросы.
- `src/service.py` — слой бизнес-логики и управления границами транзакций.
- `src/main.py` — HTTP-слой (FastAPI), валидация входных JSON-схем (Pydantic) и обработка ошибок.
- `tests/test_api.py` — интеграционные и конкурентные тесты.

## 3. Обоснование механизма транзакций и конкурентности
Для исключения отрицательного остатка при одновременных запросах на последние единицы товара используются:
1. **Атомарный условный `UPDATE` в PostgreSQL:**
   - При резервировании: `UPDATE products SET stock = stock - %s WHERE id = %s AND stock >= %s`. PostgreSQL накладывает строчную блокировку (`RowExclusiveLock`) на изменяемую запись, поэтому при одновременном обращении двух транзакций к последней единице товара условие `stock >= %s` выполнится только для одной из них.
   - При отмене заказа: `UPDATE orders SET status = 'Cancelled' WHERE id = %s AND status = 'Reserved'`, что гарантирует однократный возврат резерва даже при параллельных запросах на отмену.
2. **Детерминированный порядок обработки позиций (`sorted(items, key=lambda x: x.sku)`):** все транзакции обновляют строки товаров в строгом алфавитном порядке `SKU`, что исключает взаимные блокировки (*deadlocks*).
3. **Ограничения на уровне схемы БД:** `CHECK (stock >= 0)` страхует целостность данных на уровне СУБД.

## 4. Развертывание и запуск (WSL / Ubuntu)
```bash
# 1. Запуск PostgreSQL и создание баз данных
sudo service postgresql start
createdb warehouse_db
createdb warehouse_test_db

# 2. Настройка виртуального окружения Python
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 3. Настройка переменных окружения (секреты не хранятся в Git)
cp .env.example .env
export DATABASE_URL="postgresql://santyev-v-v:1234@localhost:5432/warehouse_db"

# 4. Запуск сервера (схема migrations/init.sql применяется автоматически при старте)
uvicorn src.main:app --host 0.0.0.0 --port 8000
```
Интерактивная документация Swagger UI доступна по адресу: `http://localhost:8000/docs`.

## 5. Спецификация эндпоинтов

### 1) `POST /api/products` — Создать товар
- **Request JSON:**
  ```json
  {"sku": "NB-1", "name": "Laptop", "price": "1000.00", "stock": 5}
  ```
- **Response `201 Created`:**
  ```json
  {"id": 1, "sku": "NB-1", "name": "Laptop", "price": "1000.00", "stock": 5}
  ```
- **Ошибки:** `409 Conflict` (дубликат SKU), `422 Unprocessable Entity` (некорректная цена или остаток).

### 2) `GET /api/products` — Список товаров с пагинацией и поиском
- **Query-параметры:** `search` (поиск по `sku` или `name`), `limit` (1..100, по умолчанию `20`), `offset` (`>= 0`, по умолчанию `0`).
- **Response `200 OK`:**
  ```json
  {"items": [{"id": 1, "sku": "NB-1", "name": "Laptop", "price": "1000.00", "stock": 5}], "total": 1, "limit": 20, "offset": 0}
  ```

### 3) `GET /api/products/{id}` — Получить товар по ID
- **Response `200 OK`:** объект товара.
- **Ошибки:** `404 Not Found` (товар не найден).

### 4) `PATCH /api/products/{id}/stock` — Изменить остаток товара
- **Request JSON:** `{"delta": -2}` (изменение на величину) или `{"stock": 8}` (установка точного остатка).
- **Response `200 OK`:** обновлённый объект товара.
- **Ошибки:** `404 Not Found` (товар не найден), `422 Unprocessable Entity` (итоговый остаток `< 0`, либо переданы оба/ни одного поля).

### 5) `POST /api/orders` — Создать заказ и зарезервировать товары
- **Request JSON:**
  ```json
  {"items": [{"sku": "NB-1", "quantity": 2}]}
  ```
- **Response `201 Created`:**
  ```json
  {
    "id": 1,
    "status": "Reserved",
    "created_at": "2026-11-26T07:00:00Z",
    "items": [
      {"product_id": 1, "sku": "NB-1", "name": "Laptop", "quantity": 2, "unit_price": "1000.00"}
    ]
  }
  ```
- **Ошибки:** `404 Not Found` (неизвестный SKU), `422 Unprocessable Entity` (нехватка остатка по любой из позиций или дубль SKU в запросе).

### 6) `GET /api/orders/{id}` — Получить заказ с позициями
- **Response `200 OK`:** объект заказа со списком позиций и зафиксированными ценами.
- **Ошибки:** `404 Not Found` (заказ не найден).

### 7) `POST /api/orders/{id}/cancel` — Отменить заказ и вернуть резерв
- **Response `200 OK`:** объект заказа со статусом `"Cancelled"`.
- **Ошибки:** `404 Not Found` (заказ не найден), `409 Conflict` (повторная отмена уже отменённого заказа).
